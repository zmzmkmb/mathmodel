# 赛题分析与建模设计

## 执行模式：两阶段建模

本 skill 不再一次性完成所有子问题的建模。而是分两阶段：

- **阶段一（全局分析）**：Step 1-6。拆解所有子问题 → 逐题软画像 → 分层知识库检索 → 假设预检 → 数据理解与来源登记。产出全局认知和每个子问题的**初步**建模方向。
- **阶段二（逐题详细建模）**：Step 7-9。对每个子问题**逐一**完成详细建模、推导和六项检查，通过后立刻交给 `3coding-visual` 跑代码与红队验证。确认可行后建模手再回到本 skill 做下一题。**下一题的建模必须参考前面已验证的真实结果**，保持模型间连续性。

## 数学建模规范参考

如需领域判断，读取 `../_references/math_modeling_norms.md` 中的"赛题理解与子问题识别""假设与模型建立"和"题型防错速查"小节。

必须读取 `../_references/workflow_gate_protocol.md`，按其中规则执行逐题机理/数据/优化软画像、推导先行、六项检查、模型深度和数据溯源。

同时读取 `../_references/workflow_state_protocol.md`。进入全局分析或某个子问题建模时更新对应阶段；完成推导门后登记 `derivation_qN` 门禁和分析产物。

如需参考历年优秀论文的建模方案，优先调用项目后端的统一知识库检索 CLI。它会融合本地 YAML 知识条目和已授权的 Pro 案例卡；`../_references/modeling_knowledge_base.md` 只作为 CLI 不可用时的静态兜底。

## 必须产出

- `reports/ANALYSIS_MODELING_REPORT.md`：赛题分析、子问题拆解、逐题软画像、数据与附件理解、假设预检、各子问题详细建模、模型深度、代码任务清单
- `analysis/derivations.md`：逐题定义、推导、可求解形式和六项检查记录
- `data/SOURCES.md`：题面附件、外部数据和关键参数的来源、处理与用途

不要在本阶段写论文正文，不要生成最终 `paper/`，不要把图表排版任务提前到这里。

## 阶段一：全局分析（Step 1-6，只做一次）

开始前运行：

```bash
python "<项目根>/backend/scripts/workflow_state.py" stage --name analysis --status in_progress
```

### Step 1: 子问题拆解

只把题面中明确编号的顶层问题当作子问题，例如"问题一/二/三""Problem 1/2/3"。不要把小问、背景描述、数据说明、提交要求误当成独立子问题。

在 `ANALYSIS_MODELING_REPORT.md` 开头写：

> 本赛题共 X 个子问题。

每个子问题说明：输入数据、决策变量/预测对象、目标函数/评价指标、约束条件、与其它子问题的依赖关系。

### Step 2: 输出建模画像

在确定任务类型和选择模型时，先读取 `../_references/model_selection_guide.md` 中的决策树，按题目特征精准选型（不要凭记忆猜）。

先对**每个子问题**分别评估机理、数据和优化成分，给出 0-1 分数、建议路线、置信度、题面证据和待确认项。三者不互斥；附件存在与否不能一票裁决。画像允许在 EDA、推导或编码后修订，分类本身不是硬门禁。

建模手再对题目的数学结构做分析，形成**初步的建模思路**，输出"建模画像"：

```text
任务类型: 预测 / 评价 / 优化 / 分类 / 聚类 / 机理分析 / 仿真 / 统计分析（可多选）
逐题软画像: 问题1=机理0.7/数据0.4/优化0.8（建议机理+优化，置信度中，证据...，待确认...）
检索关键词: 5-8个建模术语（如"时间序列预测"而非"用电量预测"）
数据条件: 小样本 / 时间序列 / 缺失值 / 多源数据 / 非线性 / 高维 / 物理常量
核心难点: 非线性耦合 / 预测误差传播 / 多目标权衡 / 约束非凸
```

**这个画像是下一步去知识库中精准检索的依据。** 不要把"任务类型"笼统写成"建模"。

### Step 3: 知识库检索（用画像精准查库，必须执行！）

**3.1 运行统一检索：** 根据 Step 2 的任务类型和关键词调用项目根目录下的 CLI：

```bash
python "<项目根>/backend/scripts/search_knowledge.py" \
  --task-types "预测,优化" \
  --keywords "时间序列,库存,鲁棒性" \
  --top 6 \
  --format markdown
```

- 将示例参数替换为当前题的建模画像；不要用题目背景词代替建模术语。
- CLI 默认融合 `backend/app/core/knowledge/data/modeling.yaml` 和同级已授权 `math-modeling-skill-pro/cases/`；可用 `MATHMODEL_PRO_KB_PATH` 覆盖案例库位置。
- 仅在 CLI 无法运行时，才用 `Read` 读取 `../_references/modeling_knowledge_base.md`，并在报告中说明检索降级。

**3.2 分层使用：**
- **Pro 证据案例（主）**：用于历史类比、来源复核、适用边界和可迁移规律；不得照搬参数与结论。
- **本地方法卡（辅）**：用于补充候选模型、求解链、验证与可视化；不得单独承担来源证明。
- **规则与验证层（硬约束）**：用于确定必须完成的推导、验证和红队测试。
- 未命中 Pro 案例时必须明确写出，不得用方法卡伪装成历史证据。

**3.3 记录匹配结果：**

```markdown
## 知识库检索结果

| 条目 | 知识层 | 关键经验 | 来源与边界 |
|---------|---------|---------|---------|
| pro:case-003 | Pro 证据案例 | 先把机理计算转成统一收益/成本，再做组合搜索 | 可追溯案例；不可照搬其参数与约束 |
| local-method:xxx | 本地方法卡 | 一维简化、二分搜索与网格检查 | 方法增强；不能单独证明模型优越 |
```

### Step 4: 知识库反哺 —— 改进建模思路（关键步骤！）

**这不是走过场。** 查完知识库后，建模手必须**逐条对照知识库的发现，明确修正自己的初步建模思路**。

#### 4.1 逐条对照：知识库发现 → 建模改进

对每条匹配到的决策卡片，逐一回答"我的方案要改什么"：

```markdown
## 知识库反哺：建模思路改进

### 来自 cumcm-2018a（物理建模+优化）的改进

知识库经验：
- 盲目的三维模型 → 改为：一维简化（厚度远小于面内尺寸）
- 忽略空气层 → 改为：IV层空气间隙必须纳入PDE系统
- 直接给定材料参数 → 改为：根据附件数据反演热扩散系数

对我建模的改进：
1. 【新增约束】之前打算做三维仿真，改为先做一维简化模型，如果精度不够再升级
2. 【补充变量】之前忽略了空气间隙，现在把IV层空气厚度作为关键变量
3. 【参数来源】之前打算直接用文献值，现在改为从附件数据反演关键参数

### 来自 cumcm-2020a（多目标优化）的改进

知识库经验：
- 只优化峰值温度 → 改为：同时优化峰值温度+液相时间+升温斜率
- 忽略辐射传热 → 改为：高温区对流+辐射同时考虑

对我建模的改进：
1. 【多目标】之前打算只优化一个目标，现在改为至少考虑2-3个关联目标
2. 【边界条件】之前只考虑了对流，现在高温区补充辐射边界条件
```

#### 4.2 对每个子问题的改进总结

```markdown
### 各子问题建模方向（改进后）

问题一：
- 改进前：三维传热仿真 → 改进后：一维热传导PDE + FDM求解
- 改进前：文献参数 → 改进后：附件数据反演参数
- 预期避坑：不忽略空气层、不盲目三维

问题二：
- 改进前：单目标优化 → 改进后：多目标优化（峰值+时间+斜率）
- 改进前：对流边界 → 改进后：对流+辐射混合边界
```

**如果知识库未命中**：在每个子问题的改进栏写"知识库无匹配，需严格走自检清单"，并对每个模型选择逐个论证。

#### 4.3 输出改进后的全局建模画像

```text
【改进后建模画像】
任务类型: (同 Step 2，如需调整则更新)
核心模型: 一维PDE + FDM + 多目标PSO（根据知识库改进后选定）
关键避坑: 不忽略空气层、不盲目三维、辐射不可忽略、多目标而非单目标
验证策略: 网格无关性检查 + CFD对照 + 物理量纲验证
```

**做完 Step 4 后，建模思路才真正定型。** 后续的假设预检、数据理解、逐题详细建模，都基于这个改进后的方案。

### Step 5: 假设敏感性预检

列出关键歧义，对影响结果的歧义至少给出两种解释，用简单验算判断选择。包含：模糊表述及解释、快速验算与递进性检查、最终采用的解释。

如果某个假设会让后续问题的新增条件没有边际效果，要回头调整。

### Step 6: 数据理解与总体路线

对每份附件做数据理解：行列规模、字段解释、缺失/异常/重复/单位不一致、可直接用于建模的变量、需要派生的指标。

创建或更新 `data/SOURCES.md`，登记题面附件、外部数据、人工录入参数和文献参数的来源、获取日期、许可/使用边界、清洗变换及用途。即使只使用官方附件，也要明确记录。

给出总体路线：`题面 → 数据清洗(EDA) → 子问题一模型 → 子问题二模型 → ... → 结果检验 → 论文展示`

## 阶段二：逐题详细建模（Step 7-9，与编码交替执行）

**从这一步开始，不再一次性完成所有子问题建模。每做完一个建模立刻编码验证，下一题参考真实结果。**

### Step 7: 逐题建模 —— 每个子问题的详细模板

开始第 N 问前登记 `model_qN` 为 `in_progress`。推导通过后登记：

```bash
python "<项目根>/backend/scripts/workflow_state.py" gate --name derivation_qN --status PASS --evidence "analysis/derivations.md#问题N"
python "<项目根>/backend/scripts/workflow_state.py" stage --name model_qN --status completed
python "<项目根>/backend/scripts/workflow_state.py" artifact --name analysis_report --file reports/ANALYSIS_MODELING_REPORT.md --required
```

存在未解释 `FAIL` 时必须登记门禁为 `FAIL`，不得把 `model_qN` 标为完成。

对第 k 个子问题（k=1,2,3...），按以下结构写详细建模方案：

```markdown
## 问题{k}模型

### 方法画像与深度目标
- 机理/数据/优化成分：0-1 分数
- 建议路线、判断证据、置信度和待确认项：
- 若画像已修订，记录修订原因：
- 目标深度：L1 / L2 / L3
- 深化点或停留在 L1 的客观限制：

### 与前序问题的衔接
[如果 k>1，必须写！]
- 利用前面已验证的真实结果（直接引用数值，不重新假设）
- 前面子问题的哪些输出作为本问题的输入
- 本问题与前面模型的递进/依赖关系
[如果 k=1，此项省略]

### 问题目标
[一句话说清要求什么]

### 符号与变量
[本问题引入的新符号，与全局符号表保持一致]

### 模型选择与理由
- 本问题属于什么类型（预测/评价/优化/...）
- 为什么选这个模型，与备选方案的对比
- 参考了知识库中哪条决策卡片的经验

### 目标函数 / 核心公式
[公式清晰、每个参数标明来源——数据统计/文献/实验测定三选一]

### 约束条件
[完整列出，优化类必须包含每个变量的物理上下界]

### 求解方法
[算法选择理由 + 核心步骤 + 停止条件 + 可行性说明]

### 推导门与六项检查
[同步写入 `analysis/derivations.md`：定义与前提 → 引理/关键关系 → 推导 → 可求解形式]

| 检查 | 结论 | 证据/待编码验证项 |
| --- | --- | --- |
| 量纲 | PASS/WARN/FAIL | |
| 退化 | PASS/WARN/FAIL | |
| 不变量 | PASS/WARN/FAIL | |
| 边界与误差 | PASS/WARN/FAIL | |
| 适定性 | PASS/WARN/FAIL | |
| 反例 | PASS/WARN/FAIL | |

### 预期输出
[输入哪些数据 → 输出哪些结果 → 绘制哪些图表 → 如何校验]
```

**写完一个子问题后先过推导门。** 只有可求解形式完整且六项检查没有未解释的 `FAIL`，才转交 `3coding-visual`。代码只能实现已批准的可求解形式；拿到常规验证和红队测试结果后，再评估是否调整建模并继续下一题。

#### 建模手拿到代码结果后的判断

- ✅ 结果符合预期 → 记录真实数值，进入下一个子问题
- ⚠️ 模型不如预期 → 分析原因：代码/数据问题让代码手修；模型选型不当则修改方案
- ❌ 完全不可行 → 参考知识库备选方案，切换模型重新设计+编码

#### 下一题建模时的连续性检查

1. 符号和变量与前一题一致（同一个量不能有两个符号）
2. 前面跑出的真实参数值直接引用，不重复拟合
3. 如果前面模型表现影响了本题选型思路，明确说明

### Step 8: EDA + 敏感性分析

数据成分较高的子问题必须在建模早期完成 EDA，不能等到全部子问题结束后才发现数据问题；机理成分较高且参数为确定常量时，用几何、量纲和物理一致性检查替代无意义的分布图。全部子问题求解完毕后，再统一汇总全局敏感性分析：

```markdown
## EDA 与数据预处理
[根据全局分析确定的题目类型，执行完整 EDA]

## 敏感性分析
[基于所有子问题的真实结果]
- 选择对全局结论影响最大的 2-4 个参数
- 变动范围有依据（传感器精度/文献范围/±20%）
- 至少 1-2 张敏感性图（龙卷风图或敏感性曲线）
```

```markdown
| 问题二 | ✅ | 最优值=42.3, 约束全部满足 |
| 问题三 | ⏳ | 依赖问题二输出 |
| EDA | ⏳ | 待执行 |
| 敏感性分析 | ⏳ | 待执行 |
```

## 高分组合方案 & 模型选择

完整的决策树（预测/评价/分类/优化/统计/文本/仿真）、高分组合方案、工程优化铁律，统一见 `../_references/model_selection_guide.md`。

## 工程优化铁律

详见 `../_references/model_selection_guide.md`。核心：每个优化变量必须有物理上下界，不能只求数学极值。

## EDA 方案区分

- **物理/力学机理题**（参数为确定常量）：不做描述性统计/直方图/箱线图。EDA 聚焦几何推导、量纲检查
- **数据驱动题**（有真实数据集）：完整 EDA（缺失值/异常值/分布/相关性分析）

## 质量要求

- 所有结论能回到题面或数据，不编造
- 不跳过歧义分析
- 模型既有数学表达也能被代码实现
- 若数据不足或题面不清，明确记录风险和替代方案
- **每做完一个子问题建模后必须交给代码手验证，不能一口气全部建完模**
- 交给代码手前必须完成 `analysis/derivations.md` 对应章节和六项检查
- 所有核心模型必须标注 L1/L2/L3；全部为 L1 时必须说明客观限制和深化尝试
