# 编程实现与数据图表生成

本 skill 与 `2analysis-modeling` **交替执行**，也支持由 `solve-and-validate` 语义路由到单个问题。局部调用只处理当前 `qN`，不自动推进后续问题；完整执行模式才按旧流程交替执行。

每次被调用时，建模手已完成**一个子问题**的详细建模方案。你的任务是：把这个子问题的方案跑出来，返回真实结果，供下一题建模参考。

开始前读取 `../_references/workflow_gate_protocol.md`。本阶段负责落实推导门之后的实现，并用常规验证和红队测试检验建模声明。

同时读取 `../_references/workflow_state_protocol.md`。开始第 N 问编码时登记 `code_qN=in_progress`，完成后登记问题状态、验证门禁、结果报告和代码产物。

## 执行模式：每次只做一个子问题

1. `2analysis-modeling` 完成一个问题建模 → 暂停
2. 转入本 skill → **只做这一个子问题**的编码求解
3. 跑出结果 → 验证 → 生成图表 → 用 print() 输出数据特征
4. 返回真实结果给建模手 → 建模手继续下一题

## 阶段边界

- 本阶段负责：代码、实验运行、结果、结果表、数据驱动图表
- 本阶段不负责：流程图/架构图（`4drawio`）、论文正文（`5writing`）
- **关键**：如果当前子问题不是第一次调用本 skill，先读取前面已跑出的结果，确保代码的输入输出与前面衔接


### Step 1: 代码结构

按 `plan.md` 中"项目目录结构"创建 `code/` 和 `figures/` 骨架，再开始写代码。子问题数不一定是 3，按赛题实际数量调整。


### Step 2: 逐子问题实现

按子问题顺序实现，不要一次性写完不跑。

编码前检查 `analysis/derivations.md` 是否存在当前子问题章节，且包含可求解形式与六项检查。若缺失或存在未解释的 `FAIL`，返回 `2analysis-modeling` 补齐；不要自行猜测并实现另一套模型。实现中若必须改变目标函数、约束、输入输出或算法假设，先回写推导和建模报告。

同时检查 `workflow_state.json` 中的 `derivation_qN` 为 `PASS`，然后运行：

```bash
python "<项目根>/backend/scripts/workflow_state.py" stage --name code_qN --status in_progress
```

每个子问题必须完成：

1. 读取所需数据。
2. 实现模型或算法。
3. 验证约束。
4. 输出核心结果。
5. 绘制丰富的图表。
6. 在 `reports/RESULTS_REPORT.md` 中写清楚方法、关键数值和校验结果。
7. 执行至少 3 类与当前模型相关的红队测试，并保存输入、输出、判定和失败解释。

优化类问题必须先保证可行解，再优化目标值。预测类问题必须做训练/验证划分或合理误差评估。评价类问题必须说明指标方向、归一化方法和权重来源。

画像驱动的验证要求（按成分叠加，不互斥）：

- **机理成分**：检查不变量、无噪声恢复、边界/退化输入、多解或无解、收敛性与数值误差下限。
- **数据成分**：检查数据泄露、留出或滚动验证、简单基线、分层误差、不确定性或校准。
- **优化成分**：检查可行域、物理上下界、约束残差、基线求解器和收敛稳定性。
- **机理+数据接口**：分别验证两层，并检查参数估计、代理模型或预测误差的传播。

### 数据特征输出规范（关键！必须遵守）

**每张图的绑图代码后，必须用 `print()` 输出该图的关键数据特征。**
这是因为后续写作阶段无法"看到"生成的图片，只能看到代码的文本输出。
没有数据特征输出，写作手将只能猜测图片内容，导致论文描述与图片不符。

不同图表类型的输出模板：

**时间序列图**：
```python
print("【图X数据特征 - 时间序列】")
print(f"   时间范围: {df['date'].min()} 至 {df['date'].max()}")
print(f"   起点值: {y.iloc[0]:,.2f}, 终点值: {y.iloc[-1]:,.2f}")
print(f"   整体趋势: {'上升' if y.iloc[-1] > y.iloc[0] else '下降'}")
print(f"   峰值: {y.max():,.2f}, 谷值: {y.min():,.2f}")
```

**模型评估图**：
```python
print("【图X数据特征 - 模型拟合】")
print(f"   R²: {r2:.4f}")
print(f"   MAE: {mae:.4f}, RMSE: {rmse:.4f}, MAPE: {mape:.2f}%")
print(f"   拟合质量: {'优秀' if r2 > 0.9 else '良好' if r2 > 0.7 else '一般'}")
```

**相关性热力图**：
```python
print("【图X数据特征 - 相关性】")
print(f"   最强正相关: {var1} vs {var2} (r={max_corr:.3f})")
print(f"   最强负相关: {var3} vs {var4} (r={min_corr:.3f})")
```

**特征重要性图**：
```python
print("【图X数据特征 - 特征重要性】")
for i, (feat, imp) in enumerate(importance_df.head(5).values):
    print(f"   {i+1}. {feat}: {imp:.4f}")
```

**预测图（含置信区间）**：
```python
print("【图X数据特征 - 预测结果】")
print(f"   点预测值: {prediction:,.2f}")
print(f"   95%置信区间: [{ci_lower:,.2f}, {ci_upper:,.2f}]")
```

**混淆矩阵**：
```python
print("【图X数据特征 - 混淆矩阵】")
print(f"   总样本数: {cm.sum()}")
print(f"   总体准确率: {accuracy:.1%}")
```

**每个子任务完成后必须输出结果汇总**：
```python
print("=" * 60)
print("【本问题建模结果汇总】")
print(f"   模型类型: {model_name}")

print(f"   核心结论: ...")
print(f"   生成图片: ...")
print("=" * 60)
```

### 数据泄露防范（预测类问题必查）

- 时序特征：用 `shift(1)` 获取上一期，**禁止** `shift(-1)`（用了未来信息）
- 滚动特征：`rolling(w).mean().shift(1)` 排除当期
- 标准化/归一化：**只用训练集 fit**，测试集 transform
- 目标编码：只用训练集计算统计值
- 时序问题**不能随机打乱**数据再划分

### 参数来源记录要求

**所有关键参数必须有来源说明**（数据统计/文献引用/网格搜索三选一），在代码注释或 print 中说明参数选择依据。禁止出现无解释的"默认值"。

### 代码出错时的反思与重试机制（核心能力！）

代码执行出错后，不是简单"改一下再试试"，而是要按照结构化的诊断流程进行**深度反思**。这是区分"会调 bug"和"真正解决问题"的关键。

#### 反思诊断框架（出错后必须逐项排查）

代码执行遇到错误后，按以下 **7 个维度**逐项诊断：

```
1. 语法错误 → 检查括号匹配、缩进、引号、中文标点混入
2. 缺失 import → numpy/pandas/matplotlib/scipy/sklearn 是否已导入
3. 变量名/类型错误 → 变量是否定义、类型是否正确（str vs int、list vs array）
4. 文件路径问题 → 相对路径是否正确、文件名拼写、编码检测
5. 数据问题 → 空值导致除零、列名不存在、shape 不匹配、dtype 错误
6. 数值问题 → 除零、log(0)、矩阵奇异、梯度爆炸、收敛失败
7. 逻辑问题 → 约束写反、索引偏移、排序方向错、条件判断遗漏
```

**每次出错后必须在修复代码前先输出诊断结论**：
```python
print(f"【错误诊断】错误类型: {error_type}")
print(f"   原因: {root_cause}")
print(f"   修复方案: {fix_strategy}")
```

#### 重试策略（防止死循环）

| 重试次数 | 策略 |
|---------|------|
| 第 1 次 | 仔细看错误栈，精准修复 |
| 第 2 次 | 简化代码，分步执行，中间打印变量值 |
| 第 3 次 | **切换方法**——换一种实现路径，换一个库，或者简化模型 |
| 第 4+ 次 | **主动降级**——如果复杂模型一直报错，退回到简单基线模型（如 XGBoost→线性回归，GA→网格搜索） |

**关键原则**：
- 同一方法最多试 3 次，超过必须换思路
- **禁止**陷入"微调代码→报错→再微调"的死循环
- **禁止**在错误发生时询问用户"怎么办"——自行诊断并修复
- 如果某个子问题确实无法完美解决，**记录前提下继续下一个**，不要卡死整个流程

#### 任务完成自检清单（每个子问题完成后必须过一遍）

代码跑通不报错了 ≠ 任务完成了。每个子问题完成后必须用以下 **12 项清单**逐条检查：

```
1. ☐ 所有要求的数据处理步骤都完成了吗？
2. ☐ 所有必要的文件都保存了吗（图片、结果表、中间数据）？
3. ☐ 还有没有遗漏的步骤？
4. ☐ 是否使用与任务声明匹配的验证指标、基线和阈值，并说明为什么足以支持结论？不得用固定 R² 阈值替代任务判断。
5. ☐ 图表是否清晰、美观、符合论文标准？
6. ☐ 约束条件是否全部验证通过？
7. ☐ 数值结果是否合理（没有数量级错误、符号错误）？
8. ☐ 关键中间过程是否记录了？（数据摘要、模型参数、迭代历史）
9. ☐ print() 输出的数据特征是否足够论文写作使用？
10. ☐ 代码是否可复现？（固定 random seed，记录依赖版本）
11. ☐ 是否完成至少 3 类相关红队测试，并记录失败、边界和修复？
12. ☐ 实现是否仍与批准的可求解形式一致，模型深度证据是否充分？
```

**完成确认**：12 项全部通过 → 输出"本问题完成✅"并给出简短总结。有未通过项 → 继续修复或把客观限制写入结果报告。

### Step 4: 生成数据驱动图表

根据 `reports/ANALYSIS_MODELING_REPORT.md` 和 `reports/RESULTS_REPORT.md` 规划图表，生成 PDF 到 `figures/`。

典型图表：

- 预测类：真实值-预测值对比、误差分布、指标对比。
- 优化类：收敛曲线、成本对比、资源利用率、方案前后对比。
- 评价类：综合得分排序、雷达图、热力图、敏感性曲线。
- 数据理解：分布图、趋势图、相关性图、箱线图。

图表要求：

- PDF 矢量输出，适合论文。
- 不在图内写大标题，标题交给论文 caption（Typst 的 `caption:` 或 LaTeX 的 `\caption{}`）。
- 中文论文图表使用中文坐标轴和图例；英文论文使用英文。
- 不生成流程图/架构图/路线图。

图表可以由主程序或独立脚本生成，不强制固定脚本名。无论采用哪种方式，都必须保存图表对应的数据来源和生成记录。

### 可视化规范（学术论文标准）

#### 预配置变量（代码沙盒已注入，直接使用）

代码沙盒启动时已注入以下变量：`CJK_FONT`、`COLORS`、`DEFAULT_COLORS`、`FIG_SINGLE`、`FIG_DOUBLE`、`FIG_WIDE`、`FIG_SQUARE`，以及字体与 matplotlib 样式 rcParams。

**严格禁止**在代码中调用 `sns.set_theme()` 或修改 `font.*` / `font.sans-serif` / `axes.unicode_minus`（否则会覆盖中文字体导致方框）。

绑图时直接使用预置变量，示例：
```python
import matplotlib.pyplot as plt
import seaborn as sns

fig, ax = plt.subplots(figsize=FIG_SINGLE)
sns.lineplot(x=x, y=y, ax=ax, color=COLORS['primary'])
ax.set_xlabel('时间 (月)')
ax.set_ylabel('产量 (吨)')
plt.savefig('trend.png', dpi=300, bbox_inches='tight')
plt.close()
```

#### 严格禁止
- 3D 图表（除非展示真 3D 数据）
- 饼图（改用水平条形图）
- 图表内大标题（用论文 caption，不要 `ax.set_title()`）
- 密集网格线
- 四边完整边框（只保留左+下）
- 低分辨率输出（用 300dpi）

#### 必须遵守
- 去掉上右边框（已通过全局配置实现）
- 使用统一的 COLORS 配色方案
- 折线图用 `fill_between` 添加置信带
- 标注关键统计量（r, p, R²）
- 子图编号用 (a), (b), (c)
- 图例无边框（`frameon=False`）
- 清晰的轴标签（含单位）
- 图例位置不遮挡数据
- 参考线标注（如基线、阈值）

#### 图表类型选择速查

| 数据类型 | 推荐图表 | 避免使用 |
|---------|---------|---------|
| 趋势/时序 | 折线图+置信带 | 纯折线无 CI |
| 分布比较 | 箱线图/小提琴图 | 柱状图+误差棒 |
| 相关性 | 散点图+回归线+r 值 | 只有散点 |
| 分类对比 | 水平条形图 | 3D 柱状图 |
| 参数敏感性 | 热力图/等高线/带阴影折线 | 多条折线堆叠 |
| 后验分布 | 密度图/直方图+KDE | 只有点估计 |

#### 图片数量建议
- 单个建模问题：4-6 张
- 敏感性分析：2-3 张
- 数据预处理/EDA：2-3 张
- 全文合计：13-18 张

### 优化类问题的工程约束（极易被扣分）

优化不能只求数学极值，必须检查实际物理可行性。具体到代码实现：

- **每个优化变量必须有上界和下界**，在代码注释中写清约束来源（几何限制/物理限制/题目要求）
- 如果无约束解违反物理限制，**在 print 中写出对比**："无约束解为 XX，但其物理不可行（如构件超出模型高度），因此引入约束 XX ≤ XX_max，约束下最优解为 YY"
- 评委看到这种工程思维分析会给高分

### 物理机理题 vs 数据驱动题的 EDA 区分（代码实现）

在写 EDA 代码前先判断题目类型：
- **物理/力学机理题**（参数为题目给定的确定常量）：**不要画直方图、箱线图**或提"异常值清洗"。EDA 代码聚焦于：打印关键参数表格 → 几何关系计算 → 量纲验证 → 物理一致性检查。
- **数据驱动题**（有真实数据集）：执行完整的 EDA 流程（`.info()`, 缺失值报告, IQR/Z-score 异常值检测, 分布图, 相关性热力图, 分组对比）。
