# 建模工作流质量门协议

本协议用于增强现有 `1start -> 2analysis <-> 3coding -> 4drawio -> 5writing -> 6verity` 工作流，不新增并行流程，也不替代各 Skill 的既有职责。

设计借鉴自 MIT 授权项目 `Ruoyu-Tianyi/MathModeling`（参考版本：commit `e7215a0`，2026-08-12），内容已按本项目的逐题建模与编码闭环重新组织。只迁移通用方法，不复制其知识库、模板或完整流程文本。

## 1. 逐题软画像

每个子问题分别记录机理、数据和优化成分，不给整道题贴固定标签，也不要求三者互斥。

| 成分 | 识别信号 | 建模重点 | 对应验证工具 |
| --- | --- | --- | --- |
| 机理 | 几何、物理机制、微分方程、守恒关系、确定性参数 | 假设、量纲、边界条件、可解性、数值误差 | 不变量、退化情形、边界与极值、多解/无解、收敛或误差界 |
| 数据 | 样本数据、预测、分类、评价、统计推断 | EDA、数据切分、基线、泛化、泄露防范、不确定性 | 留出/滚动验证、基线比较、泄露检查、误差分层、校准或置信区间 |
| 优化 | 决策变量、目标函数、资源或工程约束 | 可行域、物理上下界、求解器选择、多目标权衡 | 可行性、约束残差、基线求解器、收敛稳定性、最优性或界 |

每项使用 0-1 软分数，并记录建议路线、置信度、题面证据和待确认项。附件存在与否不能一票裁决；画像允许在 EDA、推导或编码验证后修订。画像只负责选择工具，不是阶段通过条件。

```markdown
- 机理成分：0.7
- 数据成分：0.4
- 优化成分：0.8
- 建议路线：机理 + 优化
- 判断置信度：中
- 证据：存在守恒关系、连续决策变量和工程约束
- 待确认项：两个参数是否需要从附件估计
- 允许修订：是
```

## 2. 推导先行门

编码前必须在 `analysis/derivations.md` 为当前子问题留下可审计推导。最低结构如下：

```markdown
## 问题 k：<标题>

### 方法画像与目标
- 机理/数据/优化成分：
- 建议路线、证据、置信度与待确认项：
- 可检验目标：

### 定义、符号与前提

### 引理或关键关系

### 推导过程

### 可求解形式
- 输入：
- 输出：
- 目标函数/损失函数：
- 约束与边界：
- 算法及停止条件：

### 六项检查
| 检查 | 结论 | 证据/待验证项 |
| --- | --- | --- |
| 量纲 | PASS/WARN/FAIL | |
| 退化 | PASS/WARN/FAIL | |
| 不变量 | PASS/WARN/FAIL | |
| 边界与误差 | PASS/WARN/FAIL | |
| 适定性 | PASS/WARN/FAIL | |
| 反例 | PASS/WARN/FAIL | |
```

只有“可求解形式”完整，且六项检查没有未解释的 `FAIL`，才可交给 `3coding-visual`。代码只能实现已批准的可求解形式；若实现中需要改变模型，先回写推导与建模报告。

## 3. 六项检查口径

1. **量纲**：等式两侧、目标函数各项、归一化和单位换算是否一致。
2. **退化**：零输入、常数输入、空集合、单样本、无约束或参数趋零时是否回到合理情形。
3. **不变量**：守恒量、概率和、排序、容量、非负性、几何对称性等是否保持。
4. **边界与误差**：变量上下界、误差传播、数值截断、置信范围是否明确。
5. **适定性**：解是否存在、是否唯一、是否连续依赖输入；若不满足，如何正则化或选解。
6. **反例**：主动构造能推翻假设、指标或算法的情形，并说明模型的适用边界。

不是每项都必须得到理论证明，但“不适用”必须说明理由，不能留空。

## 4. 运行后红队测试

每个子问题运行后至少执行 3 类与模型相关的测试，并保存输入、输出、判定和失败解释：

- 退化输入：全零、常数、重复样本、空类别或最小规模。
- 极端参数：允许范围的上下界、数量级变化、稀疏/密集极端。
- 边界情形：等号约束、容量恰好用满、临界阈值、时间窗口首尾。
- 噪声扰动：测量误差、缺失、异常点、标签噪声或参数扰动。
- 对抗构造：专门针对当前假设、评价指标或启发式算法构造困难样例。

失败不等于必须弃用模型，但必须修复，或把影响、适用范围和替代方案写进结果报告。

## 5. 模型深度分级

- **L1 基线**：直接应用标准模型或单一算法，主要用于可行性与比较基准。
- **L2 适配**：针对题目加入有依据的特征、约束、损失、求解策略或验证设计。
- **L3 深化**：有明确推导的新组合/新机制，包含不确定性、鲁棒性、理论性质或跨模型闭环，并有消融或对照证据。

每个核心模型须标注深度等级和证据。允许使用 L1，但若所有核心模型均停留在 L1，必须明确记录客观限制、尝试过的深化方案及未采用原因。

## 6. 数据来源与证据链

项目存在附件、外部数据、人工录入参数或文献参数时，维护 `data/SOURCES.md`：

```markdown
# 数据与参数来源

| ID | 文件/参数 | 来源或获取方式 | 获取日期 | 许可/使用边界 | 清洗或变换 | 用于哪些结论 |
| --- | --- | --- | --- | --- | --- | --- |
```

核心结果必须能沿以下链条追溯：

`论文结论 -> RESULTS_REPORT -> 结果文件/图表 -> 代码与配置 -> 原始数据/参数来源`

题面附件也要登记为“赛题官方附件”。若没有外部数据，写明“本项目仅使用题面与官方附件”，不要省略该文件。

## 7. 阶段通过条件

- **进入编码前**：逐题方法画像及证据已记录；推导与可求解形式存在；六项检查无未解释 `FAIL`。画像分类本身不决定通过与否。
- **离开编码前**：常规验证通过；至少 3 类红队测试有记录；关键结果、失败和边界写入 `RESULTS_REPORT.md`。
- **进入写作前**：核心模型深度已标注；数据来源完整；结论均可追溯。
- **最终 PASS 前**：推导、六项检查、红队证据、深度和来源均被 `6verity` 核验。
